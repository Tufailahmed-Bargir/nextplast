1. Project Overview

Problem Statement

Household plastic is often discarded without sorting, tracking, or fair incentives. Informal collection lacks verification, recyclers cannot reliably source graded stock, and users have no transparent reward for participating in recycling.

Solution

NexPlast is a full-stack circular platform: users upload waste photos, AI estimates plastic type and risk, collectors verify weight/quality with OTP, inventory is stocked, recyclers purchase lots (platform revenue), Nature Coins credit the user wallet, and coins redeem eco products in the marketplace.

Objectives

  • Digitize plastic sell → pickup → verify → reward.
  • Use AI as a trust layer (detection, confidence, fraud heuristics).
  • Operate role-based ops for User, Collector, Recycler, Admin.
  • Close the loop with inventory sales and marketplace engagement.
  • Measure environmental impact and gamify participation.

Business Model

Leverv1.0 Status
Plastic lot sales to recyclersLive — purchase records INR at unit price × kg
Marketplace margin / commissionReady via product pricing
Brand partnershipsFuture architecture
Government contractsFuture architecture
Carbon creditsFuture architecture (impact metrics seed the claim)

Circular Economy Flow

Plastic Waste → User Submit → AI Detect → Collector Verify
       → Platform Inventory → Recycler Purchase (Revenue)
       → Nature Coins → Marketplace Redeem → Repeat Engagement

Nature Coin System

Internal reward unit (not cash-withdrawable). Credited after collector verification based on verified weight, quality, and category rates. Spent in marketplace (coins, cash, or hybrid).

Marketplace System

Eco products with categories, search/filters, wishlist, cart, hybrid checkout, orders, reviews, and PDF invoices.

AI Integration

Images upload to Cloudinary. Next.js server calls FastAPI YOLOv8 (or local fallback). Bounding boxes, class counts, confidence, duplicate-image hash, and risk score feed the listing.

User Roles

USER

Sell plastic, wallet, marketplace, impact, leaderboard.

COLLECTOR

Assigned pickups, OTP, verify weight, proof, complete.

RECYCLER

Browse platform lots, purchase, history.

ADMIN

Users, listings, inventory, AI flags, analytics, exports.

8. Recycler Flow

Recyclers use /recycler (not the household dashboard). They browse platform-owned inventory lots, purchase a quantity (kg), and see order/history.

Inventory movement

  1. Validate available platform stock (reject if would go negative).
  2. Record payment (unitPriceInr × kg) — primary live revenue path.
  3. PLATFORM inventory OUT + movement; Recycler inventory IN + movement.
  4. Audit/admin log for the purchase.

Future workflow

Invoices, delivery SLAs, quality disputes, B2B contracts, and carbon certificate export.

Image Upload → Cloudinary → Next.js server

10. Nature Coin System

Rule of thumb for demos: ≈ 100 g = 1 coin ⇒ 1 kg ≈ 10 coins. Actual credit uses configured category rates × verified weight × quality/bonus factors — never quantity of items alone.

20 kg example

At 10 coins/kg baseline → ~200 coins (before quality/category multipliers).

  • Internal reward — cannot withdraw as INR.
  • Marketplace — full coin, cash, or hybrid (shipping may remain cash).
  • Wallet — balance + pending + ledger history; admin adjustments audited.
  • Rollback — transactional checkout; failed spend does not leave partial debit.

  • Python 3.10+ (AI service)
  • PostgreSQL via Neon (or local)
  • Cloudinary account
  • Google OAuth credentials (optional but recommended)

App setup

bun install
cp .env.example .env          # fill secrets — never commit .env
bun run db:generate
bunx prisma migrate deploy

cd services/ai-service
python -m venv .venv
# Windows: .\.venv\Scripts\activate

21. Project Flow Document

Full content previously in PROJECT_FLOW.md.

Problem Statement

Plastic waste collection is fragmented. Households lack incentives, collectors lack verification tools, and recyclers lack clean supply data. Fake photo submissions and manual weight disputes reduce trust in recycling programs.

Solution

NexPlast is a circular-economy web platform that connects users, collectors, recyclers, and admins. Users upload plastic photos for AI-assisted detection, schedule pickups, earn Nature Coins, and redeem them in an eco marketplace. Collectors verify weight/quality; admins oversee the economy.

Objectives

  1. Digitize plastic sell → pickup → verify → reward.
  2. Integrate practical computer vision (YOLOv8) for detection and fraud heuristics.
  3. Implement a closed-loop Nature Coin marketplace (no cash conversion).
  4. Deliver role-based dashboards for a college-scale deployment (<50 concurrent users).

Technology Stack

LayerTechnology
FrontendNext.js 15 App Router, React 19, Tailwind CSS 4
BackendNext.js Route Handlers + Server Actions
DatabasePostgreSQL (Neon) + Prisma ORM
AuthAuth.js (credentials + Google OAuth)
MediaCloudinary
AIFastAPI + Ultralytics YOLOv8
Docs / DemoCSV export, PDF (pdf-lib), QR (qrcode), Nodemailer

Architecture

Browser clients never call FastAPI. Next.js authenticates users, proxies AI requests, persists results in Prisma, and serves dashboards.

User → Next.js → Prisma/Postgres
              ↘ Cloudinary
              ↘ FastAPI /detect (API key)

Database Design (high level)

Core models: User, UserProfile, Wallet, PlasticListing, ListingImage, AiDetectionResult, PickupRequest, CollectorVerification, Inventory, Product, Order, Notification, Leaderboard, EnvironmentalImpact, AuditLog.

AI Workflow

  1. User uploads listing images (Cloudinary).
  2. Server fetches bytes → FastAPI /detect (or local fallback).
  3. Persist boxes, confidence, fraud alerts on AiDetectionResult.
  4. Duplicate image hash + low confidence + quantity mismatch checks.
  5. Weight estimate is preview-only; collector verification is final for coins.

Marketplace Workflow

Browse → wishlist/cart → hybrid payment split → order → wallet SPEND (coins) → tracking → review.

Collector Workflow

Assigned pickups → navigation → on-site verification (weight/quality/OTP) → coins credited → impact updated.

Admin Workflow

Users/roles, collector/recycler approval, listings review, inventory, coin economy, analytics, CSV exports, platform settings.

Future Scope

Fine-tuned plastic models, Redis queues, SMS OTP, QR scanning, richer Excel packs, recycler B2B marketplace.

Advantages

End-to-end recycling loop, measurable impact, practical AI, RBAC, demo-ready seed data.

Limitations

College-scale (not multi-region DevOps), YOLO uses COCO-mapped classes unless fine-tuned, email requires SMTP configuration, QR scan not implemented.

22. Viva Q&A Bank

Full content previously in VIVA_QUESTIONS.md — 60 short Q&As for final-year viva.

  1. What is NexPlast? A circular-economy platform for plastic recycling, AI detection, collector verification, Nature Coins, and an eco marketplace.
  2. Why Nature Coins instead of cash? To keep rewards inside the recycling loop and avoid cash-out fraud; coins redeem only in the marketplace.
  3. How many grams equal one Nature Coin? About 100 g of standard recyclable plastic (documentation rule).
  4. What is the internal INR value of a coin? Approximately ₹0.50 — accounting value only, not convertible cash.
  5. Which framework powers the web app? Next.js 15 (App Router) with React 19.
  6. Why Server Components? Reduce client JS, keep secrets server-side, stream UI with Suspense.
  7. What is a Server Action? A server-executed mutation callable from forms/UI without a separate REST handler.
  8. How is auth implemented? Auth.js (NextAuth v5) with credentials + Google OAuth and JWT sessions.
  9. What is RBAC? Role-based access control — middleware and guards restrict routes by UserRole.
  10. Name the main roles. USER, COLLECTOR, RECYCLER, SELLER, ADMIN, SUPER_ADMIN.
  11. What ORM is used? Prisma 6 against PostgreSQL (Neon).
  12. Why Prisma migrations? Versioned schema changes that stay reproducible across environments.
  13. Where are listing photos stored? Cloudinary; DB stores URL/publicId/metadata/hash.
  14. Why hash images? Duplicate-image fraud detection via SHA-256 content hash.
  15. What does the AI service do? Detects plastic-like objects, counts them, returns boxes/confidence/weight preview.
  16. Which model family? Ultralytics YOLOv8 (default yolov8n).
  17. Why FastAPI separately? Keeps heavy CV deps out of Next.js; independent scaling and Python ML stack.
  18. How does Next.js talk to FastAPI? Authenticated server proxy /api/ai/* with X-AI-API-Key.
  19. Can the browser call FastAPI? No — by design.
  20. What if AI service is down? Local image-analysis fallback so sell flow still works.
  21. List fraud checks. Duplicate hash, low confidence, quantity mismatch, AI reject, weight discrepancy.
  22. Is AI weight final? No — preview only; collector verification sets reward weight.
  23. What is Confidence Engine? Combines model score, image quality, category certainty, fraud pressure.
  24. How are recommendations generated? Rule-based (wallet, listings, orders, impact, seasons) — no ML recommender in v1.
  25. Explain sell plastic flow. Draft → upload → AI → edit counts → details → schedule pickup → submit.
  26. What happens after pickup verification? Coins credited, impact updated, listing completed, notifications sent.
  27. How is OTP secured? Hashed in DB; fail counts tracked; raw OTP not stored.
  28. Hybrid payment meaning? Split merchandise between cash INR and Nature Coins; shipping remains cash.
  29. How is double checkout prevented? Checkout id + Postgres advisory lock + cart clear in transaction.
  30. What is inventory used for? Platform stock after verified collections; admin adjustments audited.
  31. Admin cannot mutate AI prediction columns — why? Preserve inference integrity; review decisions are separate.
  32. Soft delete vs hard delete? Soft delete sets deletedAt / deactivates; retains audit history.
  33. What does CSV export support? Users, listings, orders, inventory, wallet txs, leaderboard.
  34. PDF library used? pdf-lib for invoices/statements/summaries architecture.
  35. QR library used? qrcode for pickup/order/listing/referral payloads (scan workflows future).
  36. Email library? Nodemailer with templates; logs when SMTP unset.
  37. Dark mode approach? next-themes with navbar toggle.
  38. How is global search scoped for users? Products + own listings + own orders.
  39. Admin search? Dedicated admin global search across users/listings/pickups/products/orders.
  40. Environmental metrics tracked? Plastic grams, CO₂, trees, ocean plastic, water, energy, oil.
  41. Leaderboard periods? Weekly, monthly, all-time (schema).
  42. What is an AuditLog? Append-only trail for sensitive actions (AI inference, admin ops, recommendations).
  43. Why Zod? Runtime validation of forms/API bodies aligned with TypeScript types.
  44. What is middleware doing? Auth gate + role redirects for /admin, /collector, /sell, etc.
  45. How do you prevent duplicate AI processing? Skip when listing image content hash already has a matching result (unless force retry).
  46. Business benefit for colleges/cities? Measurable recycling, student engagement, transparent rewards.
  47. Limitation of current YOLO mapping? COCO classes mapped to plastic labels; fine-tuned plastic weights are future work.
  48. Why not Docker/K8s in this phase? College demo targets maintainable <50-user deploy without complex DevOps.
  49. How to seed demo data? bun run db:seed creates admins/users/collectors/recyclers/listings/orders.
  50. Demo password? Demo@12345 for *@demo.nexplast.local accounts.
  51. What is AiDetectionResult.rawPayload? JSON with boxes, analysis, fraud alerts, timing, plastic types.
  52. How are Nature Coins calculated at verification? Weight × quality multiplier ÷ grams-per-coin (platform constants).
  53. What is profile completion? Heuristic over name/email/image/phone/city/address/bio.
  54. Referral QR purpose? Share invite codes; scanning workflow deferred.
  55. How would you improve accuracy next? Train custom YOLOv8 on labeled plastic datasets + human-in-loop review.
  56. Security basics? Auth, RBAC, ownership checks, rate limits on AI APIs, hashed passwords (bcrypt 12), hashed reset tokens.
  57. What is Prisma server-only used for? Prevent accidental client bundling of DB/AI secrets.
  58. Marketplace reviews require? Delivered orders (integrity of ratings).
  59. Collector rating field? Stored on Collector profile; updated with completed pickups.
  60. One sentence thesis of NexPlast? Turn household plastic into verified impact and marketplace value using AI-assisted trust.

1. Project Summary

NexPlast is a circular-economy web platform that connects households, collectors, recyclers, and admins. Users sell recyclable plastic with AI-assisted detection, collectors verify weight/quality, inventory is stocked, recyclers purchase lots (platform revenue), Nature Coins reward users, and coins redeem eco products in the marketplace.

5. Strengths

  • End-to-end reward loop is real (verify → coins → marketplace spend).
  • Inventory never decremented below zero in recycler purchase TX.
  • AI never exposed to browser; duplicate-hash fraud checks persist.
  • Hybrid payments preserve merchandise vs shipping cash rules.
  • Demo seed + embedded Project Flow + Viva Q&A sections support viva.

6. Known Limitations

  • Coupons / brand partnerships / government contracts / carbon credits = future architecture only.
  • YOLO uses COCO→plastic mapping unless fine-tuned weights are provided.
  • Email delivers only when SMTP env is set (otherwise logged).
  • Pickup statuses IN_TRANSIT / AWAITING_SIGNATURE exist in schema but are not required by the live machine.
  • Not designed for multi-region DevOps (no Docker/K8s by choice).

7. Future Scope

Fine-tuned plastic models, Redis AI queues, SMS OTP, collector QR scan, richer Excel packs, B2B contracts & carbon credit export.

25. Admin Ops Guide — What to Do on Every Screen

Login: admin1@demo.nexplast.local / Demo@12345 → home /admin. Use this during viva when professors ask “What can the admin do?”

Dashboard

/admin

What you see: high-level counts — users, pickups requested/in-flight/completed, inventory snapshot, marketplace pulse.

What to do: open the cards/links to jump into Pickup Requests, Inventory, or Analytics. Use it as the “mission control” opening slide.

Users

/admin/users

What you see: searchable user table with role, active flag, coins, recycled grams.

What to do:

  • Filter by role (USER / COLLECTOR / RECYCLER / SELLER).
  • Change role (e.g. promote a user to COLLECTOR / RECYCLER) — only admins assign operational roles.
  • Activate / Suspend accounts (blocks login when inactive).
  • Do not demote/suspend yourself.

Collectors

/admin/collectors

What you see: collector roster — zone, on-duty, verification status, completed pickups, rating.

What to do: verify who is available before assigning pickups; check performance after demo pickups complete.

Recyclers

/admin/recyclers

What you see: partner companies, contact, verification status.

What to do: confirm recycler accounts exist for the Buy Inventory demo; review verification status.

Listings

/admin/listings

What you see: plastic sell listings with status, weight claims, user.

What to do: review/flag suspicious listings; track which listings are awaiting collector vs completed. Ties to AI fraud review.

Pickup Requests (critical for demo)

/admin/pickup-requests

What you see: “Awaiting assignment” queue + recent pickups.

What to do:

  1. Find the user’s newly submitted pickup.
  2. Choose a collector (e.g. Collector 1).
  3. Click Assign.

Result: pickup ASSIGNED, user receives OTP in notifications, collector sees the job.

Inventory

/admin/inventory

What you see: platform (and related) stock lots by category/grade/grams.

What to do: after collector completes verification, refresh — platform stock should increase. After recycler purchase, stock should decrease. Explain movements / no negative stock.

Products — how admin adds marketplace products

/admin/products

What you see: create form at top + product table (activate/deactivate).

How to add a product (step-by-step):

  1. Go to /admin/products.
  2. Fill the form:
    • Name — e.g. “Recycled PET Tote Bag”
    • Slug — auto from name or type manually (recycled-pet-tote-bag)
    • Description — short eco story
    • Category — pick from dropdown (Home & Living, Personal Care, Bags, Stationery, Kitchen…)
    • Price INR — cash price
    • Price Coins — Nature Coin price
    • Stock — available units
    • Eco score — 0–100
    • Materials — comma-separated (e.g. Recycled PET, Organic cotton)
    • Image URL — public https image (Pexels/Cloudinary). Leave blank only if you accept default/empty.
  3. Click save / create — product appears in the table as active.
  4. Open user Marketplace /marketplace (other browser) and confirm the product shows.

Other product actions:

  • Activate / Deactivate in the product table — hides inactive items from shoppers.
  • Seed starter catalog button (if catalog empty) — inserts demo eco products with images.

Orders

/admin/orders

What you see: marketplace orders (user, payment mode, status, amounts).

What to do: after a user checkout demo, verify the order appears here; explain coins vs cash/hybrid.

Coin Economy

What to do:
